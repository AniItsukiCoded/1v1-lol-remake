- When the function is deployed, it is used first; direct mode is only the fallback.

# 1v1.Arena v3 — Battle Royale update

Built on top of v2 (the server economy, rules, owner tools and party system are unchanged). "Tested" means it was run; see the last section.

## New: Battle Royale

- Its own mode (`br` in `js/modes.js`), first card in the mode picker, own matchmaking rooms. Zone Wars is untouched.
- **One continuous match**: warm-up island → countdown (starts with the 2nd player, 25 s, or at once when full) → match → last player standing → Victory Royale. No respawns.
- **Player cap 10** (`max` in the mode entry). That is what the Realtime-Database netcode carries; it is one number to raise once the networking can take more. Nothing pretends to be 100 players.
- A started match is **locked** in matchmaking. Anyone who still arrives (party link) only spectates.
- **Spawns** spread on a ring around the island; **storm** with 5 phases over 5 min 20 s (damage 1 → 12 per second); alive counter, kill counter, kill feed, spectating with next / previous player.
- Rewards go through the normal server claim: placing + eliminations, capped by lobby size. Nothing picked up in a match can reach the account inventory.

## Loot, chests, inventory

- **Start**: one Common pistol (12 rounds + 36 light ammo), the pickaxe, four empty slots, no shield, no materials.
- **Five slots + permanent pickaxe.** Keys 1-5, pickaxe key, mouse wheel; controller Y / d-pad left-right, d-pad up drops; touch: tap a slot, hold to drop.
- **Weapons**: pistol (new), SMG (new), assault rifle, shotgun. Own model, damage, fire rate, magazine, reload, spread and ammo type each.
- **Rarity** Common → Legendary changes damage (+0 / 6 / 12 / 18 / 24 %), reload time and spread. Legendary is +24 %, not more.
- **Consumables**: Shield Potion (+50 shield, 3 s), Medkit (full health, 5 s). Fire to use; refuses when already full; stacks of 3.
- **Ammo** (light / medium / shells) and material stacks are picked up by walking over them.
- **Chests**: more than 20 at fixed, seeded spots inside houses and at landmarks. Glow, prompt, 0.9 s search with progress bar, lid animation, sound, loot pops out around the chest with rarity colours.
- **Sync**: opening a chest and taking an item are database transactions (`matches/<mid>/br/r<n>/ch|it|dr|nd`). First writer wins; chest contents come from match seed + chest id, so every client spawns the same loot. Warm-up and match use separate state.
- **Full bar**: the new weapon replaces the selected slot and the old one drops. Dropping (H) and elimination put items back in the world for everyone.

## Harvesting

Trees → wood, rocks → brick/stone, scrap blocks → metal. Nodes have health (5-6 hits), a glowing weak point that counts double, shrink as they are hit, disappear when depleted, and depletion is synced. In Battle Royale the pickaxe no longer gives materials for hitting any surface. Other modes keep their old behaviour and starting materials.

## The Island

380 m square island in the sea with seven named places joined by roads: Tilted Town (crossroads, 12 houses with interiors, clock tower), Lazy Lake (lake, dock, cabins), Dusty Depot (three warehouses, scrap yard), Lonely Lighthouse (stepped hill + tower), Pine Forest (lumber camp), Rocky Ridge (terraces, boulders, radio mast), Shipping Yard (container rows, gantry crane). Groves and boulder fields sit between them. Minimap and full map show roads, water and place names.

All static geometry is one merged mesh; trees / rocks / scrap are four instanced meshes.

## First person

Default for everyone, with a one-time switch for existing saved settings (`CFG.fpv`). After that the choice (Settings or the B key) is kept.

## UI

- `css/fn.css`: one visual language across lobby, mode picker, modals, buttons, item cards, HUD bars and end screen (slanted slabs, italic display type, yellow primary action, blue glass panels).
- Mode picker: Battle Royale is a wider "featured" card.
- Battle Royale HUD (`css/br.css`): compass, alive / kill chips, hotbar with rarity colours and ammo counts, ammo reserves, interaction prompt, search / use progress, pickup notices. Hidden in every other mode.
- Shop: purchase confirmation showing price and coins left (the server still does the purchase).

# 1v1.Arena v2 — change log

Everything below is in the project files. "Tested" means it was actually run; see the last section for exactly how.

## 1. The candy exploit

**Root cause.** The whole economy was client-authoritative. `saveCfg()` serialised `CFG` (coins, candy, keys, XP, owned items, pass tiers) and wrote it to `saves/<uid>`. Any player could:

1. edit `localStorage.cfg` and reload, or type `CFG.ev.candy = 5000000; saveCfg()` in the console, or
2. write `saves/<their uid>` directly with the public web API key, or
3. (if the database rules were not the strict ones the old comments assumed — `database.rules.json` was missing from the project) write `gifts/<uid>` and let the client "claim" it.

The "about 5 million" you saw is most likely the event leaderboard's own clamp (`Math.min(tot, 5000000)`): the real stored balance can be anything.

**Fix.** The unauthorised write is no longer possible, not merely detected:

- `database.rules.json` (new): `econ`, `saves`, `flags`, `audit`, `bans`, `meta`, `ownerUids`, both leaderboards and `users/*/wins|losses` are `.write: false` for every client. Only Cloud Functions (Admin SDK) write them.
- `functions/lib/economy.js` (new): every reward, purchase, box roll, duplicate refund, quest, goal, pass tier, exchange, daily, treat, AFK drop, rank prize and equip is an action the server computes from `functions/catalog.json` (generated from the game's own data files).
- Idempotency: every request carries an id; a repeated id returns the first result. Every match id pays once.
- Replay / forgery limits: a match must have been announced to the server (`mstart`) and real server time must pass before it pays; every reported number is clamped to what the mode allows; per-day caps on XP, coins, candy, pass XP and match count.
- Ledger: `audit/econ/<uid>` gets a row (action, delta, balance after) for every committed change.
- Suspicious balances are **flagged and put on hold, never wiped** (`flags/<uid>`), for owners to review.

## 2. Bugs fixed

- Anyone could delete or cut open an opponent's walls by sending a forged build event: remote `remove` / `edit` events were applied to any piece id. Build events are now tied to their sender, rate-limited and range-checked (`beOk` in `js/game.js`).
- Leftover owner check accepted `1` / `"true"` strings; now only boolean `true`, same as the server.
- Daily reward, treat box and daily quests used the device clock and local date (changing the PC clock re-opened them). Now the server clock, UTC days.
- Party: the whole party was deleted when the leader's tab closed; a member who reloaded or lost connection was dropped for good.
- A page-wide `MutationObserver` ran a DOM query on every change in the document, including every HUD update during a match.
- Every open tab wrote to `presence/` every 3 s to measure ping (now every 12 s, paused in matches and hidden tabs).
- The watchdog forced a style recalculation every 700 ms and could wipe an account on a false positive.
- Hosting config published the whole folder; `functions/`, `tests/`, `tools/` are now excluded.
- `?event=1` in the URL switched the event on for that browser only.
- `js/party.js` was empty while the party code sat in `main.js`.

## 3. Security improvements

- Server-authoritative economy and strict database rules (above).
- Owner commands authorised server-side per call; `audit/admin` action log; `audit/denied` for refused attempts; 40 commands / minute per owner; confirmation for destructive commands; 1,000,000 cap per gift.
- Bans enforced by the rules (matchmaking, matches, parties, ranked) and by the functions, not by a hidden button.
- Maintenance mode enforced by the rules.
- Ranked rating writes bounded by rules: one result per write, 20 s apart, ±130 per result, placements capped, own entry only, no guests.
- Parties: invite-only joins, kicked-player list, single-leader hand-over all enforced by rules.
- Anti-cheat is now report-only (`cheats/<uid>`). No site lock, no tab closing, no client-side wipes.

## 4. Owner system

35 commands (see README) and a dashboard with five tabs: **Players** (search, online list, full account card: stats, currencies, inventory, flags, ban state, with every action as a button), **Economy** (flags, bans, item ids, gift everyone online), **Server** (live info, announcement, maintenance, event switch, reset), **Console** (typed commands with history), **Logs** (owner action history, IP logs).

Not added: `/mute` / `/unmute` — the game has no chat or voice.

## 5. Party system

Rewritten in `js/party.js`: create (open or invite-only), invite by username, recent-teammates list with online dots, accept / decline cards, cancel pending invites, join by code or link, ready-up (leader can only start when everyone is ready), kick, hand over leadership, privacy toggle, automatic leader succession when the leader drops, rejoin after reconnect / reload, party node removed when the last member leaves.

Limit: the 10-player cap is checked in the client only (Realtime Database rules cannot count children).

## 6. Skins

- `js/locker2.js`: full catalogue (owned and locked) with search, category / rarity / ownership filters, 4 sort orders, owned / equipped / locked states, "how to get it", and a 3D inspect viewer (rotate, zoom, 5 preview animations).
- Skin Studio: any colour (picker, hex, swatches, random), 8 materials, 8 patterns, accessory from skins you own, 12 named presets with save / load / duplicate / reset / delete.
- A custom skin is still one number, so other players see it with no protocol change and old skins are untouched. Malformed values fall back to the plain look.
- The viewer is one renderer, disposed when the locker closes.

Consequences and gaps:
- Because the Studio allows any colour, the 6 shop colours are now only convenient presets — say if you want colours limited to ones a player owns.
- **Accessory positioning** is not implemented: accessories are fixed to the rig and there are no spare bits in the synced number.
- Patterns are shader-generated from the base colour; there is no second colour and no texture upload.

## 7. Building

The existing system was already a complete Fortnite-style implementation (walls, floors, stairs, roofs, grid snapping, live preview, turbo build, materials, cell editing, pre-edits, rotation, support and collision rules). I did not rewrite it. Changed: validation of other players' build / edit / remove events (section 2). Verified in a bot match: piece selection, placement with preview, editing, forged events ignored.

## 8. Terms of Service

Gate removed. No acceptance is stored or logged (`tosv` / `tosT` are no longer written). The Terms open from the corner link with a CLOSE button. IP logging itself is unchanged — see the privacy note in the README.

## 9. Performance

Changes are the ones listed in section 2 plus: settings upload only when something changed; owner-panel timer idle unless open; locked-state observer removed. The render loop, pooling and dynamic-resolution code were already tuned and are untouched. **No FPS measurement was possible** (headless software rendering runs at about 1 FPS), so I am not claiming a measured gain.
