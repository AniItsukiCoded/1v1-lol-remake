# 1v1.Arena — v2

Browser 1v1 / team shooter with Fortnite-style building (Three.js + Firebase Auth + Realtime Database + Cloud Functions).

## v3: Battle Royale

New mode with chests, loot, a five-slot inventory, harvesting and a storm on a new island; first person by default; a restyled lobby and HUD. See the top of `CHANGELOG.md`.

Deploying is the same as v2 (`firebase deploy`). The functions must be redeployed because the reward table gained the Battle Royale mode. The database rules are unchanged.

## What changed in v2 (short)

| Area | Before | Now |
|---|---|---|
| Economy | The browser held every balance and uploaded it as one JSON blob (`saves/<uid>`). Editing `localStorage` or writing that node gave any amount of candy / coins / items. | Balances live in `econ/<uid>`, **read-only for clients**. The browser sends actions to the `econ` Cloud Function, which prices, rate-limits, de-duplicates and logs them. |
| Owner tools | Gifts and tools ran in the browser. | 35 owner commands run in the `owner` Cloud Function, authorised by `ownerUids/<uid> === true` on every call, rate-limited, logged. |
| Anti-cheat | Locked the whole site / tried to close the tab / could wipe progress on a client-side guess. | Reports only. The server rejects, flags and holds; owners decide. |
| Terms | Forced acceptance screen before anything loaded. | No gate. The Terms stay behind the "Terms of Service" link. |
| Party | Create / join by code / kick. | + invitations by username, accept / decline, invite-only parties, ready-up, safe leader hand-over, reconnect, no ghost members. |
| Skins | One flat locker list. | Catalogue with search / filters / sorting / 3D inspect, and a Skin Studio (colour, 8 materials, 8 patterns, accessory, 12 named presets). |

`CHANGELOG.md` has the full list, including what was **not** done.

## Deploying (required — the game does not work half-deployed)

The Cloud Functions need the **Blaze (pay-as-you-go) plan**. Usage for a game this size normally stays inside the free quota, but the plan must be enabled.

```bash
npm i -g firebase-tools            # once
firebase login
firebase use <your-project-id>     # the project in js/config.js

cd functions && npm install && cd ..

# 1) owners: Firebase console > Realtime Database > add   ownerUids/<your UID> = true   (boolean true, not the text "true")
#    Your UID: the "My ID" button in the game, or Authentication > Users.

# 2) everything in one go (rules + functions + site)
firebase deploy
```

Deploy all three together. Rules without functions = nobody can earn anything; site without rules = the old exploit is still open.

- The functions are deployed to `us-central1`. If you pick another region, set `window.FUNCTIONS_REGION='<region>'` in `js/config.js` and change `OPTS.region` in `functions/index.js`.
- `firebase deploy` runs `tools/build-catalog.js` first, so the server's price / reward tables are always generated from `js/events.js`, `js/cosmetics.js`, `js/gunskins.js`, `js/modes.js`. **After changing items, prices, passes, boxes or quests, redeploy the functions.**
- `database.rules.json` is generated by `tools/build-rules.js`. Edit the generator, run `npm run rules`, deploy.

### What happens to existing players

- Nothing is deleted. The first time an account signs in after the update, the server imports its old `saves/<uid>` into `econ/<uid>` (once). `saves/` then stays as a frozen backup.
- An imported balance that cannot come from normal play (more than 2.5 M coins or candy, 4 M XP, 400 keys) is **kept**, the account is **flagged**, and its **spending is paused** until an owner looks at it. Earning and playing keep working.
- Owner panel → ECONOMY → LOAD FLAGS → open the player → SHOW LEDGER → `RECONCILE` (keep / server ledger only / exact numbers).

## Owner commands

Owner panel → CONSOLE, `/help` lists them. Targets are a UID or `@Username`.

`/players [name]` `/inspect` `/playerinfo` `/kick` `/ban <player> [hours] [reason]` `/unban` `/bans`
`/givecandy` `/removecandy` `/setcandy` `/givecoins` `/removecoins` `/setcoins` `/givekeys` `/giveall <what> <amount>` `/reconcilecurrency` `/hold` `/auditplayer` `/flags`
`/givexp` `/setlevel` `/setpass` `/grantitem` `/removeitem` `/giveallskins` `/items [filter]` `/resetstats` `/resetdaily`
`/announce` `/maintenance on|off` `/event on|off|auto` `/serverinfo` `/auditlogs` `/resetall RESET ALL`

There is no `/mute`: the game has no chat or voice to mute.

## Things to know

- **Privacy:** the game still logs every player's IP address and approximate location (`iplogs/`, owners only). With the acceptance screen gone, players are no longer told before it happens. Depending on where your players are (GDPR, COPPA for under-13s) that may need a visible notice or consent. `window.IPLOG=false` in `js/config.js` switches the logging off.
- **Still client-reported** (no dedicated game server exists): hits / damage inside a match, match results, and ranked rating. They are bounded (reward caps per match and per day, minimum match time measured by the server, rating step limits in the rules) but not proven. See CHANGELOG.
- Recommended next: turn on **Firebase App Check** for the database and the functions.
